# Known issues

> Hobby project: this is the author's honest bug list. Evidence comes from an audit of the author's own deployment
> plus sandbox reproductions. Figures are rough observations from that one setup, not benchmarks.
> The original audit text is in [history/](history/).

Status legend: **Fixed in 0.2.0** — the fix is in the code and the row names the test that covers it; **Open** — known and not fixed.

## Fixed in 0.2.0

| # | Area | Issue | Evidence → fix → covering test |
|---|---|---|---|
| F1 | extension | **Queue lost-update race**: `flushQueue` wrote back a stale copy of the queue after its POST, erasing messages enqueued during the round trip (the earlier mutex only covered enqueue vs enqueue). | Sandbox: 10 messages 5 ms apart with a 30 ms server → 8 lost; 200-message flood → 75 lost and 83 duplicate posts. Fix: delivered entries are removed from the *current* queue inside the same mutex. Tests (`extension/test/background.test.js`): "a burst during a slow request loses nothing and duplicates nothing", "a flood of 100 messages is delivered exactly once, with bounded storage writes" (that one only asserts an upper bound: the quadratic write volume itself is still open, see O22). |
| F2 | server | `PRAGMA journal_mode = WAL` ran **before** `busy_timeout`, so a lock at startup killed the process. | Seen once in production (`database is locked` at boot); reproduced 7/70 starts under contention, 0/70 with the lines swapped. Now `busy_timeout` first, plus retries. Test (`local-server/test/server.test.js`): "startup waits for a lock held by another process instead of crashing". |
| F3 | server | **UTF-8 corruption**: `body += chunk` decoded each TCP chunk separately; a multi-byte character split across chunks became U+FFFD. | Reproduced (3×U+FFFD per split emoji); runs of 3–4 U+FFFD found in the author's DB. Now the body is collected as bytes and decoded once. Tests: "UTF-8 characters split across two TCP writes are stored intact", "large emoji-heavy batches (many TCP chunks) are stored without corruption". |
| F4 | server | Insert failures were logged but the response was **HTTP 200**, so the extension deleted its only copy. | Reproduced with a write-locked DB. Now one transaction per request and `500 db_error` on failure. Test: "a write-locked database answers 500 (not 200), the client retries, then it is stored once". (The synchronous DB call still blocks the event loop while it waits, see O21.) |
| F5 | server | JSONL backup appended every delivery: **more than half of the lines were duplicates** (the file grew several times faster than the database), some messages dozens of times. | Counted from the author's file. Now only newly inserted rows, no blank lines, can be disabled (`WA_NOTIFY_JSONL_BACKUP=0`). Tests: "re-delivery is idempotent: one row, one backup line", "empty batches write nothing (no blank backup lines)", "WA_NOTIFY_JSONL_BACKUP=0 disables the backup file". |
| F6 | extension | `window.__waNotifyDebug()` threw `ReferenceError: NAME_PATTERN is not defined`. | Reproduced. Test (`extension/test/injected.test.js`): "__waNotifyDebug works with a populated module registry and lists only candidates". |
| F7 | extension | `__waNotifyAttach` rejected a bare Msg collection and the output of `__waNotifyRequire` although the README said otherwise. | Reproduced. Tests: "__waNotifyAttach accepts {Msg}, a bare collection and a module export", "__waNotifyRequire output can be fed straight to __waNotifyAttach". |
| F8 | extension | Auto-detect could attach to the **Chat** collection (any export that "looks like a collection"). | Reproduced in a sandbox. Now only `Msg`-named exports/modules qualify and `WAWebChatCollection` is no longer probed. Tests: "the chat collection is never attached from a module export", "auto-detection attaches to the message collection and never to the chat collection". |
| F9 | digest | Untrusted strings (sender names, summaries) were interpolated into Rich markup: `[/x]` crashed the preview; `[chorus]` was swallowed. | Reproduced with the real script. Now escaped. Tests (`tests/test_bugfixes.py`): `test_preview_survives_markup_in_sender_and_summary`, `test_table_survives_markup_too`. |
| F10 | digest | `wa-reel-digest -fa` / `--fl` re-launched itself forever in new terminals (only exact `-f`/`--float` were stripped). | Reproduced with a stub terminal. The child's arguments are now rebuilt from the parsed options. Test: `test_float_child_never_refloats`. |
| F11 | alert | `is_fast_network`: the "≥ 25 Mbit/s" rule could only return True (slow Wi-Fi fell through to a ping that succeeds). | Reproduced. A slow Wi-Fi link now means no prefetch. Test: `test_is_fast_network`. |
| F12 | ai | API-key parsing took the first line containing the name even if commented, and kept inline comments. | Reproduced. Tests: `test_secrets_parser`, `test_get_api_key_precedence`. |
| F13 | ai | An HTTP 200 without usable text (e.g. safety block) was retried silently — 4 identical uploads per reel. | Reproduced. Now one call, logged with its `finishReason`; HTTP error bodies are logged (bounded). Tests: `test_200_without_text_is_not_retried_and_says_why`, `test_persistent_429_logs_the_error_body`. |
| F14 | menu | "Mark all as opened" marked every unopened reel, including ones that arrived while the menu was open. | Now only the listed reels (`walib.mark_opened_many`). Tests (`tests/test_menu.py`): `test_mark_all_marks_only_the_listed_reels`, `test_mark_opened_many_is_exact`. |
| F15 | ai | Predictable ffmpeg temp file `/tmp/wa_reel_opt_<id>.mp4`, not removed on failure. | Now a private `tempfile.TemporaryDirectory` that is always cleaned up. Test: `test_downscale_uses_a_private_temp_dir_and_cleans_up`. |
| F16 | extension | Delivery failures (e.g. a `401` after re-installing) looked like "server down" with no visible sign. | Now a `!` badge, a rate-limited console warning and no sending without a real pairing token. Tests: "a rejected token is made visible (badge + warning) and cleared after a success", "warnings are rate limited…", "no pairing token => nothing is ever sent (fail closed)". |

## Open

| # | Severity | Issue | Evidence / detail | Workaround |
|---|---|---|---|---|
| O1 | medium | **Re-shared reels are dropped**: `INSERT OR IGNORE` keyed by shortcode keeps the first sighting forever; a later *live* re-share of a reel first seen as history never alerts. | a small share of shared reels were re-shares, and a few of those were live alerts that were lost. | Open it from the menu. |
| O2 | medium | **Own sent reels still notify** (they are no longer prefetched). | roughly one in six live alerts were reels the author had sent to other chats (none to the self-chat). | Ignore, or filter `fromMe` in `wa-reel-alert.py`. |
| O3 | low | Image posts (`/p/`) raise a "LIVE REEL" notification. | roughly one in seven live alerts. | — |
| O4 | low | **Mixed carousels** (video + photos) show only the video. | yt-dlp returns only video entries. | Open in the browser. |
| O5 | medium (privacy) | `raw_json` stores every primitive WhatsApp attribute, including **`mediaKey` and `directPath`** (the inputs WhatsApp client libraries use to fetch and decrypt media) and base64 thumbnails as `body`; the JSONL backup repeats it. | `mediaKey` in 1 349 messages, `directPath` in 1 110. | Treat the archive as a credential store; encrypt at rest; set `WA_NOTIFY_JSONL_BACKUP=0`. |
| O6 | low | `/health` is unauthenticated and reveals the DB path (a `Host` allow-list was added in 0.2.0; test "Host header check: foreign Host is rejected with 421"). | | Bound to loopback. |
| O7 | low | **Unpaired server accepts unauthenticated writes** until the first token arrives. | O8 | low | `content.js` forwards only well-formed capture entries now (test "only well-formed capture entries are relayed…"), but any script in the page can still forge a well-formed entry, and the script loads at `document_idle` (events before that are lost). | by inspection | — |
| O9 | low | Cleanup only handles **opened** reels; unopened reels' media never expires. | by inspection | `wa-reel-cleanup` + manual deletes. |
| O10 | low | **DDL is duplicated** in `server.js` and `walib.py`; there is no schema versioning or migration. | by inspection | Change both together. |
| O11 | low | **Mixed units**: `message_ts`/`timestamp`/`opened_at` are seconds; `captured_at`/`first_seen_at` are milliseconds. | schema | Convert explicitly. |
| O12 | low | **`pkill -f title=<app_id>`** (default `title=wa-reel`) matches *any* process whose command line contains that text, including the shell that launched it (it killed an automation wrapper during testing). | reproduced once | Avoid that string in other commands' arguments; planned: track the PID. |
| O13 | low | **Hyprland snippet pitfall**: an unquoted heredoc expands `$mainMod` to nothing → `bind = SHIFT, R` captures every capital R. | seen in a generated snippet | Quote the heredoc delimiter. |
| O14 | low | Sender labels are heuristics: `from` is preferred over `author` in groups, and channel names are guessed from link-preview titles (the hard-coded `Republic` special case was removed in 0.2.0). | `local-server/lib/sender.js` | — |
| O15 | low | Summaries: `summary_status` never becomes `failed`; no retry sweep for pending summaries; on-demand downloads are not summarised unless queued; a Gemini 429/503 gets one retry per model after `Retry-After` (capped at 10 s, default 2.5 s). | about a third of live reels had no summary at audit time (image posts, rate-limited downloads, and downloads whose summary call failed) | `wa_reel_ai.py <id> --force`. |
| O16 | low | Alert loop has no per-row exception isolation (e.g. missing `notify-send` with `--autoplay` repeats one row). | by inspection | — |
| O17 | low | The `footclient`→`foot` fallback only triggers when the command cannot be *started*, not when the foot server is down. | by inspection | Run `foot --server`. |
| O18 | low | `/share/…` and `/<user>/reel/…` Instagram URL forms are not recognised. | 0 occurrences in 1 145 links, so far | — |
| O19 | info | **Local DNS stalls** (10–22 s lookups, "network unreachable" blips with `systemd-resolved` flapping between DoT and UDP) surface as network pauses/retries. | author's machine | Fix the resolver. |
| O20 | info | WhatsApp Web changes break capture without notice; Instagram/yt-dlp changes break fetching. | by nature | See [LIMITATIONS.md](LIMITATIONS.md). |
| O21 | low | The server's database calls are synchronous: while the database is write-locked the whole server (including `/health`) stalls for up to the busy timeout (5 s by default). | by inspection (it was observed as an 8.5 s stall before F4) | Keep other writers' transactions short. |
| O22 | low | **The extension rewrites its whole stored queue on every enqueue**, so a history flood writes O(n²) bytes to `chrome.storage.local`. | Sandbox: 200 messages of 3 KB wrote 63 MB; the test only bounds it ("Each enqueue rewrites the whole queue (quadratic)"). | None; the queue is capped at 10 000 entries. |
